# Домашнее задание 2: Git

В репозитории — [32 задачи](TASKS.md) и локальная проверка. Нужны Linux (для Windows — Ubuntu в WSL), Git 2.28+ и Python 3.10+.

**Дедлайн: 21 октября 2026 года, 23:59 МСК.**

## Начало работы

1. Нажмите **Use this template → Create a new repository** и создайте **закрытый (Private) репозиторий** в своём аккаунте GitHub. Если уже создали публичный, переведите его в Private до сдачи.
2. В своём репозитории откройте **Settings → Collaborators → Add people** и отправьте приглашения аккаунтам **Nikfilk2030** и **ATGsan** до дедлайна. Достаточно отправить приглашения: преподаватели могут принять их позже. Не отменяйте приглашения и не закрывайте доступ до завершения проверки. В личном закрытом репозитории GitHub роль collaborator даёт также право записи — это ожидаемо.
3. Откройте терминал Linux или Ubuntu в WSL и клонируйте **свой** репозиторий. Замените `USERNAME` и `REPO` на свой логин и название репозитория:

   ```sh
   cd ~
   git clone https://github.com/USERNAME/REPO.git
   cd REPO
   python3 hw2.py init
   ```

В WSL работайте в домашнем каталоге Linux (`~/`), не в `/mnt/c/`. Не переименовывайте свой репозиторий и не меняйте его `origin`: к адресу привязана сдача.

Для `git clone` и `git push` закрытого репозитория нужна авторизация в GitHub. При работе по HTTPS обычный пароль аккаунта не подойдёт: используйте [Git Credential Manager, GitHub CLI](https://docs.github.com/en/get-started/git-basics/caching-your-github-credentials-in-git) или SSH-ключ. Не сохраняйте токены в файлах репозитория.

`init` автоматически задаёт локальные `user.name = Student` и `user.email = student@example.invalid` в учебных репозиториях **кроме задачи №1**, где автора нужно настроить вручную по условию. Повторный `init` сохраняет ручные настройки первой задачи и обновляет настройки остальных учебных репозиториев, сохраняя решения и историю. В корневом репозитории сохраняется ваш автор из локальных или глобальных настроек Git; значения `Student` используются только для отсутствующих настроек. Контрольный репозиторий `control/` сохраняет своего автора.

## Решение и сдача

Читайте [условия задач](TASKS.md) и работайте в соответствующих папках `workspace/`. Например, задача 1 находится в `workspace/01_setup/`. Это отдельные учебные Git-репозитории; команды сдачи ниже выполняйте из корня своего репозитория.

```sh
python3 hw2.py check 1
python3 hw2.py submit 1
git add .hw2/manifest.json submissions/
git commit -m "Submit homework"
git push
```

Вместо `1` указывайте номер задачи из `TASKS.md`. `check` проверяет задачу только на вашем компьютере. `submit` создаёт архив решения в `submissions/`, но сам по себе не отправляет его в GitHub. После каждого исправления повторите `check N` и `submit N`, затем сохраните изменения коммитом и выполните `git push`. Нерешённые задачи можно не отправлять.

**Работа считается сданной, только если вы отправили [форму сдачи](https://forms.gle/1kugzZBwpvExhqoQ6) до дедлайна.** Укажите в ней ссылку на **свой закрытый репозиторий GitHub** вида `https://github.com/USERNAME/REPO`, не на этот шаблон, отдельную папку или архив. Приглашения преподавателям тоже нужно отправить до дедлайна. Без заполненной формы работа не сдана, даже если вы выполнили `check`, `submit` и `git push`.

Форму можно заполнить заранее и затем продолжать работу. Проверяется версия репозитория из **последнего `git push`, сделанного до дедлайна**. Если вы исправили ссылку или решили ещё задачи, отправьте форму повторно до дедлайна с обновлённой самооценкой: учитывается **последний ответ**. Самооценка не заменяет проверку архивов; за неверно указанную оценку преподаватель может снизить итоговые баллы по своему усмотрению.

## Баллы

За каждую зачтённую задачу начисляется полная стоимость, иначе — 0 баллов. Задачи 1–24 и 27 дают по 100 баллов; задачи 25–26 — по 150; задачи 28–32 — по 200. Максимум — **3800 баллов**.

Чтобы оценить свой результат, сложите баллы за задачи, архивы которых вы отправили и для которых `check` показал «зачтено». Оценка — наивысшая достигнутая ступень:

- 200 баллов — 1;
- 300 — 2;
- 400 — 3;
- 500 — 4;
- 800 — 5;
- 1200 — 6;
- 1800 — 7;
- 3000 — 8;
- 3500 — 9;
- 3700 — 10.

Меньше 200 баллов — 0. Например, 650 баллов соответствуют оценке 4. Окончательную сумму за задачи преподаватель определит по архивам из репозитория; возможный штраф за ошибку в самооценке применяется отдельно.

Если задачу нужно начать заново, выполните из корня репозитория:

```sh
python3 hw2.py revert 1
```

Замените `1` номером нужной задачи. Команда возвращает всю папку этой задачи к исходному состоянию: **текущие файлы, настройки и история удаляются без резервной копии**. Локальный автор `Student <student@example.invalid>` настраивается заново автоматически **кроме задачи №1**, где после сброса его нужно снова настроить вручную. Остальные задачи и уже сохранённые архивы в `submissions/` не меняются. Чтобы отправить новое решение, снова выполните `submit N`.

`workspace/` не попадает в GitHub: отправляются архивы в `submissions/`. В архиве сохраняется полное состояние учебного Git-репозитория, в том числе история, незакоммиченные изменения и `.git/config`. **Не помещайте туда токены, секреты и личные файлы.**

Если переходите на другой компьютер, снова клонируйте свой репозиторий и запустите `python3 hw2.py init`: последние отправленные архивы восстановятся. Неотправленные изменения из `workspace/` останутся на старом компьютере.
